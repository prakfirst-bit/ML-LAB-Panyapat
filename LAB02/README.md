# สรุปรายละเอียดใบงานที่ 2: Data Preprocessing

## ข้อมูลทั่วไป

**รายวิชา:** Machine Learning (04-624-201)
**สถาบัน:** ภาควิชาวิศวกรรมคอมพิวเตอร์ คณะวิศวกรรมศาสตร์ มหาวิทยาลัยเทคโนโลยีราชมงคลธัญบุรี
**Dataset ที่ใช้:** Marvel Universe Characters Dataset (ข้อมูลตัวละครจากจักรวาล Marvel จำนวน 45 ตัวละคร)
**คอลัมน์ในข้อมูล:** Character (ชื่อตัวละคร), Real Name (ชื่อจริง), Affiliation (สังกัด), Powers (ความสามารถพิเศษ), Role (บทบาท: Hero/Villain/Antihero), Power Level (ระดับพลัง)

---

## วัตถุประสงค์ของใบงาน

ใบงานนี้มุ่งให้นักศึกษาเข้าใจหลักการและความสำคัญของ Data Preprocessing ซึ่งเป็นขั้นตอนพื้นฐานที่จำเป็นก่อนนำข้อมูลไปใช้พัฒนาแบบจำลอง Machine Learning โดยครอบคลุมการตรวจสอบคุณภาพข้อมูล การทำความสะอาดข้อมูล การแปลงรูปแบบข้อมูล และการเตรียมข้อมูลให้อยู่ในรูปแบบที่เหมาะสมสำหรับการวิเคราะห์

---

## LAB1: Dataset Exploration (การสำรวจข้อมูล)

ขั้นตอนแรกคือการทำความเข้าใจโครงสร้างของข้อมูลก่อนลงมือวิเคราะห์ ประกอบด้วย:

- **Load Dataset:** โหลดไฟล์ CSV เข้าสู่โปรแกรมด้วย pandas
- **Display Shape:** ตรวจสอบขนาดข้อมูล พบว่ามี 45 แถว และ 6 คอลัมน์
- **Display Data Types:** ตรวจสอบชนิดข้อมูลของแต่ละคอลัมน์ พบว่าทุกคอลัมน์เป็นชนิดข้อความ (object) ทั้งหมด ไม่มีคอลัมน์ตัวเลขต่อเนื่องเลย
- **Display Summary Statistics:** แสดงค่าสถิติเบื้องต้น เช่น จำนวนค่าที่ไม่ซ้ำกัน (unique) และค่าที่พบบ่อยที่สุด (top/freq) ของแต่ละคอลัมน์
- **Display Missing Values:** ตรวจสอบว่ามีข้อมูลขาดหายไปในคอลัมน์ใดบ้าง
- **Display Duplicate Records:** ตรวจสอบว่ามีแถวข้อมูลที่ซ้ำกันหรือไม่
- **Display Class Distribution:** วิเคราะห์การกระจายตัวของคอลัมน์ Role พบว่า Hero มีจำนวนมากที่สุด รองลงมาคือ Villain และ Antihero ตามลำดับ ซึ่งถือเป็นลักษณะของ **Imbalanced Class** (ข้อมูลไม่สมดุล) ที่ต้องระวังหากนำไปสร้างโมเดลทำนายในอนาคต

## LAB2: Data Visualization (การมองเห็นภาพข้อมูล)

- **Histogram:** เนื่องจากคอลัมน์ Power Level มีค่าเดียวคือ "Low" ตลอดทั้งชุดข้อมูล (ไม่มีความหลากหลาย) จึงไม่สามารถทำ Histogram แบบตัวเลขได้ตามปกติ จึงปรับมาแสดงความถี่ของข้อมูลเชิงหมวดหมู่แทน ได้แก่ Role และ Affiliation เพื่อดูว่าตัวละครแต่ละกลุ่มมีจำนวนเท่าไหร่

- **Correlation Heatmap:** เนื่องจาก dataset นี้ไม่มีคอลัมน์ตัวเลขเลย จึงไม่สามารถคำนวณค่าสหสัมพันธ์ (Correlation) แบบมาตรฐานได้ (Correlation ใช้ได้กับข้อมูลตัวเลขเท่านั้น) จึงเลือกใช้ **Crosstab (ตารางไขว้)** แทน โดยนำคอลัมน์ Role และ Affiliation มาจัดเรียงเพื่อนับจำนวนตัวละครที่ตรงกับทั้งสองเงื่อนไขพร้อมกัน แล้วแสดงผลผ่าน Heatmap ผลลัพธ์พบว่ากลุ่มที่มีชื่อสื่อถึงฝ่ายวายร้าย เช่น Hydra และ Sinister Six มีสมาชิกเป็น Villain เกือบทั้งหมด ขณะที่กลุ่ม Avengers มีสมาชิกส่วนใหญ่เป็น Hero ซึ่งสอดคล้องกับความเป็นจริงในจักรวาล Marvel

## Part 3: Data Cleaning (การทำความสะอาดข้อมูล)

- **Missing Value Handling:** ตรวจสอบและเติมค่าที่ขาดหายไปด้วยคำว่า "Unknown" เนื่องจากทุกคอลัมน์เป็นข้อมูลประเภทข้อความ การเดาค่าด้วยวิธีอื่นอาจทำให้ข้อมูลผิดเพี้ยนจากความเป็นจริง

- **Duplicate Removal:** ลบแถวข้อมูลที่ซ้ำกันทุกคอลัมน์ทิ้ง เพื่อป้องกันไม่ให้ข้อมูลชุดเดียวกันถูกนับซ้ำจนวิเคราะห์ผิดเพี้ยน

- **Incorrect Data Correction:** แก้ไขข้อมูลที่ไม่สอดคล้องกัน (Inconsistent Data) เช่น ช่องว่างส่วนเกินหน้า-หลังข้อความ และการสะกดตัวพิมพ์เล็ก-ใหญ่ไม่สม่ำเสมอ โดยใช้คำสั่งตัดช่องว่างและปรับให้ตัวอักษรแรกเป็นตัวใหญ่เสมอ

- **Data Type Conversion:** แปลงคอลัมน์ที่เป็นหมวดหมู่ (Role, Affiliation, Power Level) จากชนิด object ให้เป็นชนิด category เพื่อประหยัดหน่วยความจำและสื่อความหมายว่าเป็นข้อมูลกลุ่มที่มีค่าจำกัด

- **Compare Mean vs Median:** เนื่องจากไม่มีคอลัมน์ตัวเลขที่เหมาะสม จึงสร้างตัวแปรใหม่จากความยาวข้อความในคอลัมน์ Powers เพื่อสาธิตหลักการเปรียบเทียบ โดยพบว่า Mean มีค่าประมาณ 32.07 ตัวอักษร และ Median มีค่าประมาณ 33.00 ตัวอักษร ซึ่งใกล้เคียงกัน แสดงว่าความยาวคำอธิบายพลังของตัวละครส่วนใหญ่ไม่มีค่าที่สุดโต่งผิดปกติมากนัก

---

## Part 4: Feature Engineering (การแปลงข้อมูลให้พร้อมใช้งาน)

- **Label Encoding:** แปลงคอลัมน์ Role (Hero, Villain, Antihero) ให้เป็นตัวเลข โดย LabelEncoder จะเรียงค่าตามลำดับตัวอักษรภาษาอังกฤษเสมอ ผลลัพธ์ที่ได้คือ Antihero=0, Hero=1, Villain=2 วิธีนี้เหมาะกับคอลัมน์ที่มีจำนวนหมวดหมู่น้อยและไม่จำเป็นต้องรักษาลำดับความสำคัญระหว่างกลุ่ม

- **One-Hot Encoding:** แปลงคอลัมน์ Affiliation (Avengers, X-Men, Hydra ฯลฯ) ให้กลายเป็นคอลัมน์ย่อยหลายคอลัมน์ แต่ละคอลัมน์เก็บค่า 0 หรือ 1 วิธีนี้เหมาะกับคอลัมน์ที่ไม่มีลำดับความสำคัญระหว่างหมวดหมู่ เพราะป้องกันไม่ให้โมเดลเข้าใจผิดว่ากลุ่มหนึ่งมีความสำคัญมากกว่าอีกกลุ่มหนึ่ง

---

## สรุปผลการดำเนินงาน

จากการสำรวจข้อมูล Marvel Universe Characters Dataset พบว่าเป็นข้อมูลที่มีลักษณะพิเศษคือทุกคอลัมน์เป็นข้อมูลประเภทข้อความล้วน ไม่มีคอลัมน์ตัวเลขต่อเนื่องเลย และคอลัมน์ Power Level ที่ควรจะบ่งบอกระดับพลังเป็นตัวเลข กลับมีเพียงค่าเดียวคือ "Low" ตลอดทั้งชุดข้อมูล ทำให้ต้องปรับวิธีการวิเคราะห์บางขั้นตอนให้เหมาะสมกับลักษณะข้อมูลจริง เช่น การใช้ Crosstab แทน Correlation Heatmap และการสร้างตัวแปรความยาวข้อความขึ้นมาใหม่เพื่อสาธิตหลักการเปรียบเทียบ Mean และ Median

นอกจากนี้ยังพบว่าข้อมูลมีลักษณะไม่สมดุล (Imbalanced Class) โดยตัวละครฝ่าย Hero มีจำนวนมากกว่า Villain และ Antihero อย่างชัดเจน ซึ่งเป็นประเด็นสำคัญที่ควรพิจารณาหากจะนำข้อมูลชุดนี้ไปพัฒนาโมเดลทำนายผลในอนาคต

หลังจากผ่านกระบวนการทำความสะอาดข้อมูล (จัดการค่าที่ขาดหาย ลบข้อมูลซ้ำ แก้ไขความไม่สอดคล้อง และแปลงชนิดข้อมูล) รวมถึงกระบวนการแปลงข้อมูลให้พร้อมใช้งาน (Label Encoding และ One-Hot Encoding) ข้อมูลชุดนี้มีความสมบูรณ์และพร้อมสำหรับนำไปใช้วิเคราะห์หรือพัฒนาแบบจำลอง Machine Learning ในขั้นตอนถัดไปแล้ว
